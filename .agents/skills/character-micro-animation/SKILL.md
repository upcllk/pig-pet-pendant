# 角色微动作与状态驱动

## 目标与边界

- 先区分角色内部动作与整图物理运动；平移、旋转不能替代眨眼或肢体动作。
- 复用素材、动作节奏和验证流程，不把某只角色的坐标、幅度或时间常数当作通用值。
- 不改写用户原图。提取素材或生成预览时使用独立输出，记录来源、画布、时长及必要的摘要。
- 静态图局部变形只适合眨眼、耳朵轻动和拱鼻等小动作；走路、转身、大幅拱身需原帧、分层或骨骼素材。素材不足时先明确边界，不用整图拉伸冒充。
- 仅讨论时不修改；新增动作涉及改变原造型或保护区域时先确认授权。本项目已授权气球和竹子小猪的局部变形，不代表授权重绘。

## 1. 分析输入，选择路线

确认输入类型、像素尺寸、透明度、帧数、逐帧时长、循环设置和角色连接点。查看原图与完整姿态索引，不只看首帧。

**已有 GIF / APNG / 帧序列：**

1. 保留原时长、帧序和画布；有必要才去掉独立长绳或远离角色的游离点。
2. 对齐悬挂、系绳或接触点；验证处理后保留的角色像素。
3. 按观察划分短动作；不能把人工动作命名当成自动语义识别结果。

**静态透明图：**

1. 量测眼睛、耳朵、鼻子范围及耳根等枢轴，以源图坐标或归一化坐标记录；不要从缩略图猜坐标。
2. 标明允许变形与受保护区域，包括相邻五官、轮廓、绳结、脚部、抱持接点。
3. 在原图副本上做连续局部变形，影响范围边缘平滑衰减，避免裂口、拉尖和污染相邻部位。
4. 明确工作图的重采样尺寸；“保护像素不变”必须说明是相对原图还是相对重采样后的待机副本。

## 2. 设计时间节奏与动作幅度

- 动作需有起势、变化、顶点、必要停留和恢复，而非仅设定帧数。
- 眨眼分别设计渐进闭合、闭眼停留和睁眼；当前项目约 0.2 秒停留是已使用的参数，不是所有角色的标准。
- 耳朵围绕耳根动，鼻子有可见的局部位移；不要只断言“图像发生变化”。
- 迁移到不同表情时先检查动作是否成立：本项目猪上吊的叉叉眼保持不变，将眨眼调度映射为耳朵动作，并单独保护眼部像素；不能把普通眼睛压扁逻辑套到所有角色上。
- 区分源帧数、相位采样段数、播放更新频率与导出预览帧率。本项目局部动作的 72 段相位采样不是 72 FPS，也不是 72 张原画。
- 按实际显示尺寸验证；增加姿态数不能弥补幅度过小、闭眼过短或大部分时间近乎静态。

## 3. 组织状态与衔接

- 将角色时钟与物理积分解耦；物理休眠时可继续待机动作，不因角色动作重新积分静止绳子。
- 待机随机间隔并避免连续重复；多角色分别计时，不通过多开进程实现。
- 移动检测可结合锚点与角色速度；下坠依据实际角色速度和项目坐标方向。采用平滑、滞回和冷却，避免微抖反复触发。
- 明确事件优先级与排队规则；避免当前动作中途硬切。长暂停恢复不能按暂停时长触发速度或追赶动画。
- 隐藏和系统睡眠暂停动作及等待时钟，恢复继续；模式切换是否重置按现有项目行为处理。
- 对原帧动作，先比较接缝与相邻帧，再检查眼鼻等局部。低全图差异不保证混合后没有重影。
- 优先沿相邻姿态回收到相近出口，再做短过渡；不要用延长叠化掩盖大幅姿态错位。
- 透明帧混合需保留预乘 Alpha 权重与主体不透明度，防止两次半透明覆盖导致绳子透出。
- 按全部角色的活动状态决定更新频率。缓存相同停留姿态，限制缓存内存；不为了更多采样无上限缓存所有图片。

## 4. 验证与迭代

1. **核心逻辑**：可设随机种子；检查动作顺序、随机间隔、时间有效性、过渡连续性、闭眼时长、多个输入帧率、重置与恢复。
2. **实绘特征**：正常尺寸与实际像素倍率下检查多个中间眼形、闭眼高度、耳朵和鼻孔的实际位移；不能只在放大图中验证。
3. **保护范围**：比较脚部、系绳区域及相邻五官像素；验证动作前中后接触几何、主体 Alpha 和完整轮廓。
4. **运行集成**：静止时有随机动作、移动/下坠有反应；多角色全部覆盖，非首角色活动也要影响调度；检查隐藏/睡眠暂停恢复及模式回归。
5. **用户观察**：区分编译、自动测试、实际绘制和人工体验。用户反馈动作不明显时，先检查实际节奏与正常尺寸效果，不以帧数解释或宣布已验收。

## 5. 产物与交付

- 可复用产物：姿态索引、动作划分、来源摘要、测量定义、参数依据、复现命令及必要预览。
- 临时截图、日志、偏好备份和调试包留在项目忽略目录。本项目为 `dist/`。
- 合成预览标注“实际绘制路径 + 合成输入，非实机录屏”；预览 GIF 循环不代表应用固定循环。
- 从序列合成 GIF 时精确匹配帧名、按帧号排序，检查数量和总时长，排除联系表或旧截图。
- 报告已验证行为、用户观察及尚未验证的边界。遵守项目偏好备份、单实例、构建和提交规则。
