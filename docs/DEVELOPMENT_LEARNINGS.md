# 开发经验与踩坑记录

本文整理本项目开发中已实施或验证过、且可复用的经验。项目特有的数值和素材结论不应直接推广到其他项目；自动化检查通过也不代表主观观感已确认。

## 架构与变更

- **先保持行为，再逐步重构。** 大型入口拆分时先机械搬移并回归，再调整模拟、设置、调度和绘制的职责边界；这样更容易定位回归，也避免把架构变化和手感变化混在一起。可参考 [PendantSimulation.swift](../PigPendant/Core/PendantSimulation.swift)、[SceneSnapshot.swift](../PigPendant/Presentation/SceneSnapshot.swift) 与核心测试。
- **依赖和数据流比目录数量更重要。** 核心模拟显式接收锚点和时间，绘制消费只读场景快照；这让核心逻辑可独立测试，也能验证旧快照不会随模拟继续变化。
- **参数定义与控件关联应有单一、具名来源。** 默认值、范围、保存键和说明集中定义，设置行用具名记录关联控件，避免平行数组下标错位；同时测试边界、模式切换、保存恢复和旧值迁移。

## 动画、物理与素材

- **先识别用户要改的是角色动作还是整图运动。** 平移、摆动不能替代眨眼、耳朵和四肢等角色内部动作。复用已有素材前先检查透明度、帧数、时长和画布；本项目绳子小猪参考 GIF 为 75 帧、每帧 40 ms，提取后保留的角色像素与原帧一致。详见 [绳子动画资料](ROPE_ANIMATION.md)。
- **循环接缝需要量化筛选和局部实绘检查。** 全图差异较低不保证五官自然：本项目曾出现低差异候选帧混合后眼睛、嘴部重影。先用相似度筛候选，再检查局部特征；用相邻姿态回收到待机，再短混合，通常比单纯延长叠化更可靠。指标只适用于生成它的图像处理方法，不等同于动作识别或主观自然度。
- **物理静止不等于动画结束，也不等于无需更新。** 绳子物理休眠时角色仍可播放待机动作；竹子弯垂、绳端摆动、多只气球等独立状态都要纳入休眠判定。隐藏或系统睡眠时则应暂停动画时钟，恢复后避免基于暂停时长突然跳帧。
- **把模拟状态与视觉过渡分开。** 参数变化或大幅输入不应直接重置当前姿态；视觉平滑也不应伪装成物理状态变化。测试应覆盖长帧间隔、快速转向、静止收敛及不同输入帧率。
- **验证图像的实际特征，而非只断言资源“存在”。** 素材自身 alpha 与绘制层透明度要分开检查；主体不透明度、柔边像素和闭合轮廓应分别验证，并在浅色背景上检查整体观感。状态栏动画也要按实际帧调度计算播放速度，用单调时钟推进相位，并按最大缩放倍率预留画布。
- **Windows 透明挂件的帧间混合应先合成像素，再绘制一次。** 曾把两张主体不透明的动画帧分别按 `1-t`、`t` 设置图层透明度并顺序叠画；源覆盖合成在 `t=0.5` 时的最终 Alpha 只有 75%，移动到视频等动态背景上就像透明度闪动。改为在预乘 Alpha 缓冲区对颜色和 Alpha 分别线性混合，生成单张位图绘制；自动检查验证两张不透明测试帧混合后 Alpha 仍为 255，并检查半透明边缘的预乘值。此检查能证明混合公式，实际播放器上的观感仍需实机确认。
- **静态角色的局部变形要保护邻近五官与接点。** 本次竹子小猪的眨眼区域过大，实绘中曾把鼻子上沿挤出尖角；缩小影响范围后，以鼻子粉色像素不变和闭眼高度变小分别验证，避免只看“眼睛变了”。气球底部与竹子脚部也按工作图逐像素比较；结论限于这些素材和局部小动作，不代表复现了原 GIF 的完整身体动作。
- **更多姿态不等于动作更明显。** 用户实测指出原局部眨眼短促且动作不明显；调整后分别检查渐进闭眼/睁眼、约 0.2 秒闭眼停留，以及 48 点实绘中的多级眼睛高度和耳朵/鼻孔位移。此处位移与时长是自动检查的结果，不代表用户已确认自然度；闭眼停留复用同一缓存图，避免增加采样后重复生成相同姿态。
- **白边修色和选区删除必须分别实测。** 用户否定了肤色/蓝线补色方案后，本项目实际试验全图白色色域删除：白色数量可归零，却会在五官和带子处出现透明缺口；连续选区也可能沿细白线钻进内部。用户随后选择保留内部保护，最终将外边选中的白色直接变透明、限制到原透明区域的距离；验收检查选中像素的 Alpha，而不是仅统计图像“变了”。该方式是针对当前素材的保守折中，仍需用户确认观感。
- **手工新素材优先于继续叠加自动修边。** 用户最终提供两张手工处理的单帧图，并选择以新图重做网兜耳鼻动作；本轮已移除旧补色/删白代码，而非继续叠加。新网兜的蓝网和透明网眼通过采样源/目的双侧保护保持逐像素不动，接点与动作区域按新画布重新量测；原62帧仅留作参考，新动作不能宣称恢复了原GIF。
- **分层新母版可只接收原表情帧的差量。** 幽灵猪原眨眼帧带整身外发光，新身体层没有；直接贴整帧会把旧效果带回。统一光栅与确定性缩放、量测眼部中心后，只转移眼部颜色差量并固定新身体 Alpha，本批素材对齐误差小于 0.01 像素，非眼部逐帧不变；该结论只适用于已检查的输入，替换母版后必须重新验证。
- **原表情帧与运行时肢体变形分开验收。** 幽灵猪眨眼 APNG 仍逐帧保持非眼部和 Alpha 不变；运行时才在每个表情副本上施加相同耳手/下摆变形，验证眼鼻固定及相邻帧混合不变淡。耳手按粉色特征位移检查，下摆按实际 Alpha 轮廓检查，避免只验证内部颜色变化。非方形画布的局部旋转按像素纵横比换算，不直接旋转归一化坐标。
- **持续流动不能复用偶发动作的包络。** 用户希望幽灵脚停着也像波浪流动，因此下摆改为独立循环相位，不随眨眼收尾归零；上半身仍保持原动作。自动检查分别覆盖四个圆弧脚的正常尺寸轮廓幅度、同一时刻相反方向的起伏及循环接缝，避免把全身同幅升降误当行波；隐藏/睡眠保留相位，仅在可见时持续更新。
- **可淘汰缓存不能承担最近姿态的稳定性。** 本轮 GUI 回归在连续请求同姿态的图像身份检查处中断；`NSCache` 不保证保留刚写入对象。局部绘制器单独保留最近一次结果，其余姿态仍用有预算的缓存，既稳定连续调用，也避免因淘汰而重复生成当前帧；这不代表任意历史姿态都保证相同对象。

## 模式、设置与发布

- **分层不只是把像素数值复制出来。** 本项目分离原光环时，直接改写原索引色位图会触发颜色模型错误；先转设备 RGB 又与原图的颜色管理结果不一致。最终以透明连通区域生成蒙版，保留原图颜色空间，并在统一比较色空间后验证主体、光环、柔边 Alpha 及像素互斥；此流程适用于已存在透明间隔的配件，不能直接推广到与身体粘连的图层。

- **新增模式要端到端接入。** 同步检查模式枚举、菜单、设置显隐、默认值、独立持久化、旧值迁移、资源、绘制和测试；默认模式通过不代表其他模式通过。每种模式都需要自己的切换、恢复、活动/休眠和截图回归。
- **区分自动验证、实绘检查和人工观察。** 构建成功不能证明视觉效果、点击穿透、多屏、Spaces 或全屏行为正确；报告结果时应标明是哪种验证。GUI 冒烟测试会触碰用户偏好，运行前备份到忽略目录，结束或异常退出后都要恢复。
- **发布前核对安装包本身。** `.app`、ZIP、应用版本、构建号、Release 标签和附件架构应相互一致；临时签名不等于公证，首次在其他 Mac 打开可能出现安全提示。
- **发布构建要与已验证的运行器环境一致。** 本次同一提交在 `macos-latest` 完成应用构建和核心检查，但 Release 工作流改用 `macos-15` 后，旧 Swift 编译器在 `CGFloat`/`Double` 运算处报歧义。发布流程改用已通过的 `macos-latest` arm64 运行器；跨版本编译器兼容性需要单独修复和验证，不能用一个运行器的成功代替另一个。
- **共享工作区提交时只提交确认过的文件。** 暂存失败必须立即停止后续提交；提交前检查 `git diff --cached --name-only`，确认暂存区不含并行工作。推送触发的 CI 仍在运行时不能报告为通过。
- **文档预览要诚实标注来源并检查整组输出。** 自动化渲染截图合成的 GIF 不是实机录屏；检查所有模式在联系表中的裁剪和主体大小，并确认最终素材在受版本控制的文档目录，而不是被忽略的构建输出目录。

## macOS 能力边界

- 当前 macOS SDK 不支持应用用 `CGCursorIsVisible()` 可靠读取其他应用的全局指针显隐状态，本项目也未找到受支持的全局替代 API。跟踪鼠标静止只能是近似推断，不能冒充播放器隐藏指针的可靠检测；应记录限制，不依赖私有 API。
